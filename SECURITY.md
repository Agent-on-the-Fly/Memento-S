# Security Policy

## Supported versions

Security reports are assessed against the current `main` branch and the latest
published release. Older releases may not receive fixes. A report should name
the affected version or commit so the maintainers can reproduce it accurately.

## Reporting a vulnerability

Please do not publish exploit details, credentials, private data, or a working
proof of concept in a public issue.

1. Check the repository's **Security** tab for a **Report a vulnerability**
   button and use that private channel when it is available.
2. If private vulnerability reporting is unavailable, open a minimal public
   issue asking the maintainers to arrange a private reporting channel. Include
   no sensitive technical detail in that issue.
3. In the private report, include the affected version or commit, platform,
   impact, reproduction conditions, and any suggested mitigation.

The maintainers will acknowledge the report when it has been reviewed and will
coordinate disclosure after a fix or mitigation is available. This project does
not currently promise a fixed response or remediation time.

## Scope

Reports about Memento-Skills source code and release artifacts are in scope.
Vulnerabilities in an upstream dependency should also be reported to that
dependency's maintainers; please notify this project privately when the issue
affects a supported Memento-Skills configuration.
